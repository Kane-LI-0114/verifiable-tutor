# 课程语料分块策略与混合检索的实证研究

实验报告（中文版），2026-11-19。数据来自 `experiments/chunking/` 下的 `full-01`、`rrf-weights-01`、`dual-granularity-01` 和 `dual-dense2-01`。

## 摘要

本文研究课程讲义语料上的分块策略与混合检索。语料是 13 个文档、365 页由 PPT 转换而来的课程 PDF，检索目标是让正确答案所在的页面尽量靠前，同时控制注入模型的上下文成本。我们构建了 65 道带 gold page 的题目，其中 14 道用于开发、51 道用于测试，比较了 `page_only`、`page_first` 的三种预算、`recursive` 的三种预算、`semantic` 和 `cross_page` 共九个组合，并在主实验之后做了融合权重和双粒度索引两个后续实验。

主实验的结果是：在 hybrid 检索的页级 nDCG@5 上，没有任何切法显著优于 `page_only`；`recursive_450` 和 `semantic_450` 的 0.8562 与基线的 0.8512 只差 0.005，51 道题里 1 胜 49 平 1 负，置信区间跨零。当前生产规则 `page_first_450` 与 `page_only` 统计打平，但前五页 token 少 122，真实截断率从 12.33% 降到 10.99%，并保留了一页一块的引用粒度。因此，在本次实验范围内，`page_first_450` 是综合最优：它不是分数最高的方案，但它是唯一同时满足质量、成本、引用完整性和工程简单性的方案。

后续实验进一步说明，简单的融合权重调整没有帮助，1:1 仍是最好的；双粒度索引（词法用页级块、稠密用 128 子块）把 nDCG@5 提到 0.8596，hit@3 提到 0.902，但仍不显著，且低于 dense-only 的 0.8941。双粒度是目前唯一值得继续确认的方向。

## 1. 引言

课程助教系统需要回答学生关于讲义、tutorial 和作业的问题。与普通文档问答不同，这个系统要求答案能落到具体页面，因为学生要能打开 PDF 核对原文。于是检索单元是块，引用单元是页。分块方式会同时影响两件事：块太大，向量被截断、主题被平均；块太小，上下文被切碎、词法检索失去完整性。什么样的大小和边界最适合这个语料，是本文要回答的问题。

本文的工作可以概括为三个问题。第一，在同一份语料和同一套检索配置下，哪种分块策略和预算能让正确答案页排得最前、成本最低。第二，词法检索和稠密检索对粒度的偏好是否不同，简单的融合权重能不能把两者的优势合起来。第三，如果让词法用大块、稠密用小块，做一个双粒度索引，能不能超过单一切法。

我们的贡献是：构建了一个 65 道题、页级 gold page 的课程检索评测集；完成了九个分块组合的系统比较，并同时报告页级排序质量、命中率和真实 token 成本；通过词法/稠密消融定位了两种检索对粒度的不同偏好；用融合权重和双粒度两个后续实验验证了这个偏好能不能转化为实际收益；最后给出了可复现的结论和明确的适用边界。

## 2. 背景与实验思路

分块策略大致有四类。固定窗口按字符数硬切，最简单，但会切断表格、公式和句子；递归切分按段落、句子、词、字符逐层下降，比固定窗口更自然；结构感知利用 OCR 的标题、表格、公式标签，按版面结构切；语义切分用相邻块的向量相似度判断话题边界。本文还加了一个跨页策略，用连续页的相同标题做合并，用来测试页边界是不是人为限制。

检索侧使用混合检索：SQLite FTS5 的 BM25 作为词法路，BGE-M3 的 1024 维向量作为稠密路，两路用 reciprocal rank fusion 融合。这个项目和大多数 RAG 系统一样，最终把 top-k 块交给模型，所以上下文成本必须和排序质量一起看。

固定窗口没有进入主实验。这个语料是结构化讲义，固定窗口会把表格和公式切一半，测它大概率只能得到“它很差”这个已知结论，对“哪种切法适合这个项目”没有信息量。本文把重点放在结构感知、递归、语义和跨页这四种更接近实际选择的方案上。

## 3. 语料与题目

语料是 13 个课程文档、365 页。每页由 OCR 解析成若干 block，每个 block 带标签、内容和位置。这个语料有一个很重要的结构特征：365 页里有 354 页在 450 个估算 token 以内，只有 11 页超过 450；237 页不超过 128，83 页在 129 到 256 之间，34 页在 257 到 450 之间。也就是说，在 450 预算下，绝大多数页本来就是一整块，切块只能影响少数长页。

我们还统计了页内和跨页的语义相似度。页内相邻 block 的余弦相似度中位数是 0.509，跨页边界是 0.387；在 10%、25%、50%、75%、90% 各个分位上，页内都高于跨页。这说明页边界确实是一个比较自然的语义边界。PPT 的一页通常围绕一个主题展开，标题、要点、图表都在同一页，所以整页作为一个检索单元是合理的。但这不等于“每页只有一个主题”：365 页里 103 页只有一个 `paragraph_title`，140 页有两个，51 页有三个，说明页内仍有层次。

题目共 65 道，全部是看着页面文本写的，不是看着切块结果写的。这一点很重要：如果看着切块写题，会不自觉地按现有切法出题，实验就失效了。每道题标注 gold page，并校验过文档和页码真实存在。64 道题只有一个 gold page，q027 有两个。题目按页长分层：短页 21 道、中等页 16 道、长页 28 道；按类别分：概念 21、机制 14、tutorial 13、assignment 11、表格 6。14 道 dev 只用于选语义阈值，51 道 test 用于报告所有指标。题目用英文，因为语料是英文，这样可以避免中文到英文的改写引入额外变量。

| 维度 | 数量 |
|---|---:|
| 总题数 | 65 |
| dev / test | 14 / 51 |
| 短页 / 中等页 / 长页 | 21 / 16 / 28 |
| 概念 / 机制 / tutorial / assignment / 表格 | 21 / 14 / 13 / 11 / 6 |
| 单 gold page / 双 gold page | 64 / 1 |
| gold page 估算 token 中位数 | 239.5 |
| gold page 估算 token 均值 | 255.7 |

## 4. 主实验设置

主实验比较九个组合。`page_only` 是 baseline，一页一块，不切。`page_first` 是生产规则，一页不超过预算就整页一块，超过预算先按 `paragraph_title` 分节、节内按块打包，表格、公式、图片永远不切。`recursive` 按段落、换行、句子、空格、字符逐层切分，再向上合并到预算。`semantic` 用相邻 block 的 BGE-M3 余弦相似度判断是否断开，阈值在 dev 上选。`cross_page` 把连续页里相同主标题的内容合并，是唯一允许跨页的策略。

| 组合 | 策略 | 预算/阈值 | 说明 |
|---|---|---:|---|
| `page_only` | 一页一块 | 无 | baseline，不切 |
| `page_first_128` | 生产规则 | 128 | 小预算压力测试 |
| `page_first_256` | 生产规则 | 256 | 中预算 |
| `page_first_450` | 生产规则 | 450 | 当前生产值 |
| `recursive_128` | 递归分隔符 | 128 | 不依赖 OCR 标签 |
| `recursive_256` | 递归分隔符 | 256 | 中预算 |
| `recursive_450` | 递归分隔符 | 450 | 大预算 |
| `semantic_450` | 相邻块相似度 | 450，阈值 0.25 | 阈值在 dev 上选 |
| `cross_page_450` | 跨页标题合并 | 450 | 唯一多页块策略 |

检索配置固定为：BGE-M3，1024 维，CLS pooling，L2 归一化，CPU，`max_length=512`，batch 16；FTS5 `unicode61 remove_diacritics 2` 和 BM25；RRF `k=60`，两路权重 1:1，每路取前 30 个候选。k 取 3、5、10，主指标是页级 nDCG@5。查询改写冻结成原问题，不调用 DeepSeek，保证所有方案使用同一份查询文本。

页级指标的做法是：把返回的块按排名展开成页，重复页只保留第一次出现，再截断到 k 页。nDCG 使用二元相关性，IDCG 取 min(|gold|,k)。另外报告 hit@3、hit@5、MRR 和 `context_tokens@5`，后者是产生前五页所消耗的块 token 总数。我们还用 BGE 的真实分词器统计每个块超过 512 token 的比例，作为截断诊断，不参与主评分。

统计上，同一道题上的两个方案是配对的。我们算每道题的 nDCG 差值，用 bootstrap 按题重采样 2000 次，取 95% 置信区间；命中率是 0/1，用 McNemar 精确检验。主比较只有一个：hybrid 下的页级 nDCG@5。判定规则提前写死：主指标显著更好、前三页命中不退步、上下文成本不超过 baseline 的两倍，三条都满足才换。

环境是 Python 3.12.7、torch 2.15.0+cpu、transformers 5.22.1、numpy 2.5.4、Windows 11。页面快照、题目、向量缓存、临时索引、逐题结果和汇总都在 `experiments/chunking/` 下，生产代码没有被修改。

|---:|---:|---:|---:|---:|---:|---:|
| 0.25 | 381 | 140.9 | 0.8682 | 0.8562 | 0.902 | 1008 |
| 0.30 | 452 | 118.7 | 0.8588 | 0.8562 | 0.902 | 974 |
| 0.35 | 630 | 85.1 | 0.8445 | 0.8393 | 0.8824 | 903 |

dev 选了 0.25，但 0.25 的 381 块和 `recursive_450` 的 380 块只差一个块，那个块从没进过前五，所以 test 指标完全一样。0.30 也是 0.8562，token 少 34；0.35 掉到 0.8393。语义切法在这个语料上没有中间点能赢，要么退化成页级，要么切碎后变差。

`cross_page` 只有 289 块，53 块覆盖多页。它的 hybrid 是 0.8368，词法最高 0.7803，稠密 0.8342，截断率 16.26%。它的问题不是“跨页一定不好”，而是这个实现太粗：只看每页第一个标题，忽略页内小标题，标题相同就合并，没有处理无标题页，只在 450 一个预算上跑。多页块还会让页级指标给它覆盖的每一页同样的信用。所以它只能作为边界压力测试，不能当成生产候选。

## 6. 实验二：融合权重敏感性

主实验显示词法喜欢大块、稠密喜欢小块，一个自然的问题是：能不能只调 RRF 权重，把稠密的收益带进 hybrid。我们在 `recursive_450`、`page_only`、`page_first_450` 三个目前 hybrid 最好的不同组合上试了 1:1、稠密 2:1、词法 2:1。`semantic_450` 没选，因为它和 `recursive_450` 重复。

| 组合 | 稠密:词法 | nDCG@5 | hit@3 | token@5 | 相对 1:1 的 ΔnDCG@5 | 胜/平/负 |
|---|---|---:|---:|---:|---:|---:|
| `recursive_450` | 1:1 | 0.8562 | 0.882 | 1008 | - | - |
| `recursive_450` | 2:1 | 0.8302 | 0.863 | 1018 | -0.0260 [-0.0603, 0.0005] | 2/45/4 |
| `recursive_450` | 1:2 | 0.8412 | 0.882 | 994 | -0.0150 [-0.0367, 0.0000] | 0/48/3 |
| `page_only` | 1:1 | 0.8512 | 0.882 | 1059 | - | - |
| `page_only` | 2:1 | 0.8302 | 0.863 | 1076 | -0.0210 [-0.0518, 0.0026] | 1/47/3 |
| `page_only` | 1:2 | 0.8218 | 0.882 | 1042 | -0.0295 [-0.0584, -0.0072] | 0/46/5 |
| `page_first_450` | 1:1 | 0.8487 | 0.882 | 937 | - | - |
| `page_first_450` | 2:1 | 0.8302 | 0.863 | 965 | -0.0184 [-0.0498, 0.0051] | 2/46/3 |
| `page_first_450` | 1:2 | 0.8337 | 0.882 | 923 | -0.0150 [-0.0367, 0.0000] | 0/48/3 |

所有调整都比 1:1 差。唯一不跨零的是 `page_only` 的 1:2，但它是 -0.0295，是显著退步。三个 2:1 行都是 0.8302，因为这三个组合都是页级，dense-only 分数几乎一样（0.8323、0.8319、0.8323），稠密权重一加大，融合结果就退化成同一个稠密排名。所以这次实验排除的是“在现有最好的页级组合上单靠调权重就能提升”，没有真正测试 128 小块配稠密权重会不会更好。

## 7. 实验三：双粒度索引

双粒度的做法是：词法路用 `page_first_450` 的页级块，稠密路用 `page_first_128` 的 128 子块；两路先各自展开成页、去重，再在页级做 RRF，`k=60`。模型拿整页文本，所以 token 按页算。先跑 1:1，再跑稠密 2:1。

| 系统 | nDCG@5（95% CI） | hit@3 | hit@5 | 前五页 token |
|---|---:|---:|---:|---:|
| `page_first_450` hybrid | 0.8487 [0.7532, 0.9314] | 0.882 | 0.882 | 1147.9 |
| `page_first_128` dense only | 0.8941 [0.8280, 0.9525] | 0.941 | 0.980 | 1141.5 |
| 双粒度 1:1 | 0.8567 [0.7652, 0.9340] | 0.863 | 0.902 | 1144.8 |
| 双粒度稠密 2:1 | 0.8596 [0.7819, 0.9293] | 0.902 | 0.941 | 1136.5 |

双粒度 1:1 比 `page_first_450` 高 0.0081，区间 [-0.0059, 0.0305]，2 胜 48 平 1 负，不显著。稠密 2:1 比 baseline 高 0.0110，区间 [-0.0333, 0.0595]，5 胜 42 平 4 负；相对 1:1 高 0.0029，区间 [-0.0374, 0.0447]，5 胜 43 平 3 负。两个区间都跨零。

但命中率的变化更明显：稠密 2:1 把 hit@3 从 1:1 的 0.863 拉到 0.902，hit@5 从 0.902 拉到 0.941，前五页 token 还略降到 1136.5。它是目前唯一一个把页排名往稠密方向拉、又没有明显退步的设置。不过它仍然远低于 dense-only 的 0.8941，说明页级融合还是丢掉了一部分稠密信号。这个结果值得用更多题确认，但不能当成已经成立的提升。

## 8. 成本比较

只看 nDCG 会误导，因为块大的方案可能带更多 token。下面把离线索引、在线上下文、索引规模、调参和工程复杂度放在一起比。向量按 1024 维 float32 估算，每块约 4 KB；token@5 是 hybrid 的前五页成本。

| 方法 | 离线索引 | 在线 token@5 | 索引规模（约） | 调参/工程复杂度 | 页引用 |
|---|---|---:|---:|---|---|
| `page_only` | 365 个块向量 | 1059 | 365 块，1.5 MB | 最低 | 一页一块 |
| `page_first_128` | 638 个块向量 | 586 | 638 块，2.6 MB | 低 | 一页一块 |
| `page_first_256` | 451 个块向量 | 760 | 451 块，1.8 MB | 低 | 一页一块 |
| `page_first_450` | 382 个块向量 | 937 | 382 块，1.6 MB | 低，生产已有 | 一页一块 |
| `recursive_128` | 604 个块向量 | 596 | 604 块，2.5 MB | 低 | 一页一块 |
| `recursive_450` | 380 个块向量 | 1008 | 380 块，1.6 MB | 低 | 一页一块 |
| `semantic_450` | 381 个块向量 + 3469 个 block 向量 | 1008 | 381 块，1.6 MB（block 向量为临时） | 高：多一遍 block 嵌入和阈值调参 | 一页一块 |
| `cross_page_450` | 289 个块向量 | 944 | 289 块，1.2 MB | 中：多页块映射 | 一块多页 |
| 双粒度 2:1 | 382 个页级块 + 638 个子块 | 1136.5（整页注入） | 1020 块，4.2 MB | 中高：两套索引和页级融合 | 一页一块 |

`page_only` 和 `page_first` 的离线成本最低，都是每个最终块算一次向量。`semantic` 多了一遍 3469 个 block 的嵌入，约为 chunk 数的九倍，还要在 dev 上选阈值；在我们的运行里它的在线 token 也没有更便宜，1008 对 937。`cross_page` 的索引最小，但多页块让引用和页内定位变复杂。双粒度是 1020 个块、约 4.2 MB 向量，是 `page_first_450` 的 2.7 倍离线成本，在线 token 还略高，因为模型仍然拿整页文本；它的收益主要体现在 hit@3 和 hit@5，而不是 nDCG 的显著提升。所有方案的在线稠密矩阵都不大（289 到 1020 个块），查询成本主要被 BGE 查询编码和后续 LLM 调用占据，检索矩阵乘法不是瓶颈。

## 9. 讨论

为什么页是自然单位？365 页里 354 页在 450 预算下本来就是一整块，页内相似度中位数 0.509 高于跨页的 0.387。PPT 的一页通常围绕一个主题，标题、要点、图表都在同一页，所以整页作为检索单元是合理的。切小只在长页上赚一点，在短页上亏一点，平均下来打平。这就是为什么九种切法的 hybrid nDCG 都在 0.81 到 0.86 之间，差距很小。

为什么没有显著赢家？51 道题的样本量只能排除大效应；64 道题只有一个 gold page，页级指标对长块天然友好；query 改写被冻结成原问题，生产环境的改写可能改变绝对分数；公式页 OCR 噪声很大，q011 和 q025 的失败主要来自这里，不是切法。这些都是结论的边界。

为什么生产代码仍然是最好的选择？`page_first_450` 与 baseline 统计打平，但前五页 token 少 122，截断率低 1.34 个百分点，保留一页一块的引用粒度，代码就是生产代码的参数化版本。它不是分数最高的方案，但它是唯一同时满足质量、成本、引用完整性和工程简单性的方案。`page_first_256` 是成本优先的备选：nDCG 掉 0.013 不显著，token 省 28%，截断率 4.66%。`page_first_128` 更省，但 48 个 oversize 块，单题波动更大。

未来最值得做的是什么？双粒度稠密 2:1 是唯一一个方向对、没有明显退步的设置：nDCG 0.8596，hit@3 0.902，hit@5 0.941，token 1136.5。但它没有显著赢，而且低于 dense-only 的 0.8941。下一步应该先把题目扩到 100 道左右，确认这个 0.011 的差距是不是真的；如果确认，再做多分辨率索引、reranker 或 query rewrite。继续在单一切法上换预算，边际收益很低；在现有页级组合上调 RRF 权重已经被证明是退步；`cross_page` 和当前语义配置也不值得继续。

## 10. 结论

在本次实验范围内，当前生产方案 `page_first_450` 是综合最优。它没有显著优于 `page_only`，但统计上打平，成本更低，截断更少，引用粒度更干净，工程复杂度最低。`page_first_256` 是成本优先的备选；`page_only` 是最简单的 baseline，但长页截断更多；`recursive_450` 和 `semantic_450` 分数最高但不显著，语义还有额外离线成本；`cross_page` 的粗糙实现不适合生产；融合权重 1:1 已经最好；双粒度稠密 2:1 是唯一值得继续确认的方向，但还不能替代生产。

一句话总结：**这个语料上，页是天然的检索单位，切法不是检索的瓶颈；生产代码的选择是合理的，下一步的提升不在切法，而在双粒度、reranker 和 query rewrite。**
