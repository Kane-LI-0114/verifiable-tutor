# 最合适的 chunk 策略：实验报告

## 工作概览

这个任务要回答一个问题：**在课程讲义语料上，哪种切块方式最适合 RAG 检索。** 语料是 13 个文档、365 页由 PPT 转成的 PDF；系统要回答学生问题，并把引用落到具体页面，所以检索单元是块，评测单位是页。

当前生产代码用的是 `page_first_450`：一页不超过 450 个估算 token 就整页一块，超过预算按标题和块切，表格、公式、图片不切。实验要验证它是不是最好的选择，以及有没有更值得换的方案。

我们做了三个实验。第一个比较九种切法和预算，回答“哪种切法最好”。第二个只调 RRF 的词法/稠密权重，回答“切法之外，融合能不能补”。第三个做双粒度索引，让词法用页级块、稠密用 128 子块，回答“两路各用自己喜欢的粒度能不能赢”。三个实验都使用同一批 65 道题（14 道 dev、51 道 test）、同一套 BGE-M3 + BM25 + RRF 检索，以及同一套页级指标。

## 实验一：九种切法对比

实验目的：比较 `page_only`、`page_first` 的 128/256/450、`recursive` 的 128/256/450、`semantic_450` 和 `cross_page_450`，看哪种切法让正确答案页排得最前、成本最低。

实验设计：九个组合各自建索引，用同一批 65 道题检索。主指标是 hybrid 下的页级 nDCG@5，辅助看 hit@3、hit@5、前五页 token 成本和真实 BGE 截断率。比较时按题配对，用 bootstrap 2000 次算 95% 置信区间，命中率用 McNemar 检验。切法之外的所有条件都锁死：BGE-M3、FTS5 BM25、RRF `k=60`、两路各 30 个候选、查询文本原样使用。

先看整体结果。下表是 51 道 test 题的 hybrid 页级 nDCG@5 和前五页 token。

| 组合 | nDCG@5 | 前五页 token | 截断率（BGE >512） |
|---|---:|---:|---:|
| `page_only` | 0.8512 | 1059 | 12.33% |
| `page_first_128` | 0.8405 | 586 | 1.57% |
| `page_first_256` | 0.8384 | 760 | 4.66% |
| `page_first_450` | 0.8487 | 937 | 10.99% |
| `recursive_128` | 0.8130 | 596 | 1.66% |
| `recursive_256` | 0.8488 | 811 | 5.62% |
| `recursive_450` | 0.8562 | 1008 | 10.79% |
| `semantic_450` | 0.8562 | 1008 | 10.76% |
| `cross_page_450` | 0.8368 | 944 | 16.26% |

表面看 `recursive_450` 和 `semantic_450` 最高，但和 `page_only` 只差 0.005，51 道题里 1 胜 49 平 1 负，置信区间 [-0.0077, 0.0228] 跨零。所有组合相对 `page_only` 的置信区间都跨零，没有任何切法显著更好。`page_first_450` 和 `page_only` 几乎一样，51 道题里 50 道排名相同，只输了一道 q058，但 token 少 122，截断率低 1.34 个百分点。

真正有信息量的是两路消融。词法路喜欢大块：`page_first_450` 是 0.7786，`page_first_128` 只有 0.7270。稠密路反过来喜欢小块：`page_first_128` 是 0.8941，`page_only` 是 0.8323，`recursive_128` 是 0.8747。稠密的 `page_first_128` 相对 baseline 是 +0.0618，9 胜 3 负，token 少 454，但置信区间 [-0.0031, 0.1353] 刚好碰到零，不能算显著。hybrid 打平，是因为词法的大块偏好和稠密的小块偏好互相抵消。

按页长看也是同一个故事。短页上 `page_only` 是 0.921，切小反而降到 0.902；长页上 `page_only` 是 0.824，`recursive_450` 是 0.844，`cross_page` 是 0.857。切块在长页上赚一点，在短页上亏一点，平均下来打平。这个语料 365 页里有 354 页在 450 预算下本来就是一整块，切块只能影响 11 个长页，所以全局换切法的收益空间很小。

语义切法没有赢。dev 选出的阈值是 0.25，切出 381 块，和 `recursive_450` 的 380 块只差一个块，test 指标完全一样；0.30 也是 0.8562，0.35 掉到 0.8393。它还要多给 3469 个 block 算向量、多一层阈值调参，收益没有覆盖成本。跨页切法 `cross_page` 是 0.8368，截断率 16.26%，最差；它只是一个粗糙的边界压力测试，不是生产候选。

实验一的结论：**没有切法显著优于 `page_only`；`page_first_450` 在统计上打平，但更便宜、截断更少、引用粒度更干净；`page_first_256` 是成本优先的备选；`recursive_450` 和 `semantic_450` 的高分是噪声；`cross_page` 不适合生产。**

## 实验二：融合权重

实验目的：实验一发现词法喜欢大块、稠密喜欢小块。一个便宜的问题是：只调 RRF 权重，能不能把稠密的收益带进 hybrid。

实验设计：只挑目前 hybrid 最好的三个不同组合 `recursive_450`、`page_only`、`page_first_450`；`semantic_450` 没选，因为它和 `recursive_450` 重复。权重试三档：稠密:词法 1:1、2:1、1:2。其他条件不变。

| 组合 | 1:1 | 稠密 2:1 | 词法 2:1 |
|---|---:|---:|---:|
| `recursive_450` | 0.8562 | 0.8302 | 0.8412 |
| `page_only` | 0.8512 | 0.8302 | 0.8218 |
| `page_first_450` | 0.8487 | 0.8302 | 0.8337 |

所有调整都比 1:1 差。唯一置信区间不跨零的是 `page_only` 的词法 2:1，但它是 -0.0295，是显著退步。三个 2:1 都是 0.8302，因为这三个组合都是页级，dense-only 分数几乎一样，稠密权重一加大，融合结果就退化成同一个稠密排名。

实验二的结论：**在现有页级组合上，1:1 已经最好，调权重不是提升方向。**

## 实验三：双粒度索引

实验目的：既然词法喜欢页级块、稠密喜欢 128 子块，就让两路各用自己喜欢的粒度，再在页级融合。

实验设计：词法路用 `page_first_450` 的页级块，稠密路用 `page_first_128` 的 128 子块；两路各自展开成页、去重，再在页级做 RRF，`k=60`。模型拿整页文本，所以 token 按页算。先跑 1:1，再跑稠密 2:1。

| 系统 | nDCG@5 | hit@3 | hit@5 | 前五页 token |
|---|---:|---:|---:|---:|
| `page_first_450` hybrid | 0.8487 | 0.882 | 0.882 | 1147.9 |
| `page_first_128` dense only | 0.8941 | 0.941 | 0.980 | 1141.5 |
| 双粒度 1:1 | 0.8567 | 0.863 | 0.902 | 1144.8 |
| 双粒度稠密 2:1 | 0.8596 | 0.902 | 0.941 | 1136.5 |

双粒度 1:1 比 baseline 高 0.0081，区间 [-0.0059, 0.0305]，2 胜 48 平 1 负；稠密 2:1 比 baseline 高 0.0110，区间 [-0.0333, 0.0595]，5 胜 42 平 4 负。两个区间都跨零，不能算显著。但稠密 2:1 把 hit@3 从 0.863 拉到 0.902，hit@5 从 0.902 拉到 0.941，token 还略降到 1136.5，是目前唯一一个方向对、没有明显退步的设置。

它仍然低于 dense-only 的 0.8941，说明页级融合还是丢掉了一部分稠密信号。双粒度的额外成本是离线给 1020 个块算向量（页级 382 + 子块 638），约为 `page_first_450` 的 2.7 倍；在线 token 还略高，因为模型拿的是整页。

实验三的结论：**双粒度是目前唯一值得继续确认的方向，但还没有显著赢，不能替代生产。**

## 总结：最合适的策略

把三个实验放在一起，答案很清楚：**当前生产代码 `page_first_450` 是综合最优的 chunk 策略。** 它不是 nDCG 最高的方案，但它是唯一同时满足四件事的方案：质量上和 `page_only` 统计打平，前五页 token 少 122，截断率从 12.33% 降到 10.99%，并且保留一页一块的引用粒度、没有额外模型和调参成本。`recursive_450` 和 `semantic_450` 的 0.8562 看起来高 0.005，但这是噪声；语义还多一遍 block 嵌入和阈值调参。`cross_page` 和融合权重调整都不值得。

成本放在一起看：

| 方法 | 离线索引 | 在线 token@5 | 复杂度 | 结论 |
|---|---|---:|---|---|
| `page_first_450` | 382 个块向量 | 937 | 低，生产已有 | 推荐 |
| `page_first_256` | 451 个块向量 | 760 | 低 | 成本优先备选 |
| `page_first_128` | 638 个块向量 | 586 | 低 | 最省，但单题波动大 |
| `recursive_450` | 380 个块向量 | 1008 | 低 | 分数高但不显著 |
| `semantic_450` | 381 个块 + 3469 个 block 向量 | 1008 | 高 | 不推荐 |
| `cross_page_450` | 289 个块向量 | 944 | 中，多页映射 | 不推荐 |
| 双粒度 2:1 | 1020 个块向量 | 1136.5 | 中高，两套索引 | 继续验证 |

如果要给下一步，建议先把题目扩到 100 道，确认双粒度稠密 2:1 的 0.011 差距是不是真的；如果确认，再做多分辨率索引、reranker 或 query rewrite。继续在单一切法上换预算，边际收益很低。

一句话：**这个语料上页是天然的检索单位，切法不是瓶颈；`page_first_450` 是当前最合适的选择，`page_first_256` 是成本优先的备选，双粒度是唯一值得继续验证的方向。**
