# 分块策略实验：设计、配置与结果

运行编号 `full-01`，日期 2026-11-18。所有文件都在 `experiments/chunking/` 下。

## 1. 实验目的

这个实验要回答的问题很具体：**同一批课程材料、同一套检索方法，换一种切块方式，能不能让正确答案所在的页面更稳定地排到前面，同时不要塞太多没用的内容给模型。**

先从一个真实问题说起。学生问“tiled GEMM 为什么每个 tile 要两次 `__syncthreads()`”，正确答案在 Tutorial 4 的第 14 页和第 19 页。系统要先把课程 PDF 变成一页一页的结构化文本，再切成小块，然后用关键词和向量两路去检索，最后把最靠前的几块交给模型。切块是这条链路的第一步，也是这次实验唯一要动的变量。

这里有一个很容易把实验做错的地方。假设一种切法每块 100 个词，另一种每块 400 个词，都取前五块。块大的方案一下子带进去两千个词，块小的只带进去五百个词。如果按“前五块里有没有出现答案”来算，块大的几乎一定赢，但它赢的原因是带得多、蒙中的概率大，不是找得准。所以这个实验不能按块来比，必须按页来比：把返回的块按顺序展开成页，重复的页只算一次，然后看正确答案那一页排在第几。这样块大的方案不会因为块大而天然占便宜。

举个真实的例子。q058 问 stable softmax 的三步流程，正确答案在 Tutorial 4 第 29 页。`page_only` 返回的前几页是第 27 页、第 29 页、第 28 页，正确答案排第二。页级 nDCG 给第二名的分数是 1 除以 log2(3)，大约 0.63；排第一是 1.0，排第三是 0.5。这个指标不只说“找没找到”，还区分“排得多靠前”。另外两个指标负责别的事情：前三页有没有命中，回答“用户翻三页能不能看到”；为了拿到这几页花了多少 token，回答“这个排名值不值”。

实验有三个假设。H1 是预算比策略更重要，也就是说在页级约束下，128、256、450 三个预算之间的差异，可能比不同策略之间的差异更大。H2 是结构感知的切法在表格、公式和长页上更好，因为它不会把表格和公式切一半。H3 是跨页合并能提升连贯性，但要牺牲“一块属于一页”的引用完整性，值不值得用数据判断。这三个假设分别对应结果里的主表、类别和页长分层、以及跨页对照。

这个实验评估的是“检索有没有找到正确页面”，不是“模型最后答得好不好”。所以它不能回答答案是否忠实、引用是否逐字正确，也不能回答换一门课还成不成立。它的价值在于把切块这个变量单独拎出来，在同一条检索链路上量出差异和代价。

## 2. 候选策略及介绍

实验一共有九个组合。它们不是随便凑的，每一个都代表一种判断。

`page_only` 是 baseline，意思是每一页整块保留，完全不切。它代表“不切”的下限。如果精心设计的切法连它都打不过，那切块在这个语料上就没有价值。它还有一个隐藏代价：BGE-M3 的输入窗口是 512 个 token，整页一块时，长页的尾部会被截掉。实测 365 个整页块里有 45 个超过 512 个 token，占 12.33%，最长的一页有 1944 个 token。也就是说，baseline 自己也有毛病，这个事实本身就是结果的一部分。

`page_first` 是项目现在的生产规则，我们跑 128、256、450 三个预算。它的做法是：一页如果不超过预算，就整页一块；超过预算，先按小标题分节，节内再按块打包；表格、公式、图片永远不切；单个超大的块独立成块并标记 `oversize`。450 是当前生产值，128 和 256 是压力测试，用来回答“把块切小一点会不会更好”。三个预算分别产生 638、451、382 个块，平均估算 token 是 83.8、118.9、140.5。

`recursive` 是另一种常见做法，不依赖 OCR 的标题和表格标签，只按段落、换行、句子、空格、字符一层层往下切，切完再向上合并到预算以内。它代表“别人做通用 RAG 时最常用的做法”。三个预算分别产生 604、427、380 个块。它和 `page_first` 的差别在于，`page_first` 相信版面结构，`recursive` 只相信文本分隔符。

`semantic` 是先算相邻两个块的 BGE-M3 向量相似度，话题变了就断开，同时受预算约束。它代表“按意思切”的另一种思路。阈值不能拍脑袋，我们先看了语料里相邻块相似度的分布，中位数是 0.51，四分之一分位是 0.43。阈值设到 0.6，大多数相邻块都会被判定为不相似，一页会被切成很多小碎片；阈值设到 0.25，只有不到 2% 的相邻块会断开，切出来几乎和整页一样。所以阈值网格只取 0.25、0.30、0.35，只在 14 道 dev 题上选，选完再去看 51 道 test 题。最后 dev 选了 0.25，产生 381 个块，和 `page_first_450` 非常接近。

`cross_page` 是唯一允许跨页的方案。它把连续几页里同一个主标题下的内容合成一块，直到预算用完。它用来回答“一页一块是不是人为限制了上限”。它产生 289 个块，其中 53 个覆盖多页。它可能提高连贯性，但一个块跨多页会让引用和页内定位变复杂，所以只做一个 450 的对照，不进入生产。

固定窗口我们故意没有测。它按字符数硬切，会把表格切一半、公式切一半，而这个语料是结构化讲义，不是小说。测它大概率只能得到“它很差”这个早就知道的结论，对“哪种切法更适合这个项目”没有信息量。这是设计决策，不是遗漏。

九个组合的规模如下。表里的 token 是项目自己的估算值，BGE 的真实 token 数在后面单独列，因为估算值会低估长页。

| 组合 | 块数 | 平均估算 token | 最大估算 token | oversize 块 | 多页块 |

## 3. 测试题目来源

65 道题全部是看着 `data/corpus/pages/` 里的页面文本写的，不是看着切块结果写的。这一点很关键。如果看着切块写题，你会不自觉地按现有切法出题，等于让现有方案自己考自己，实验就失效了。每道题都标了 gold page，也就是答案在哪一页，并且用脚本校验过文档和页码真实存在。出题时不直接抄页面原句，因为抄原句会让关键词检索占便宜。

题目分成 14 道 dev 和 51 道 test。dev 只用来选语义切法的阈值，test 只看一次，不能反复调。这是为了避免拿考试题调参。题目按页长分层：21 道落在短页，16 道落在中等页，28 道落在长页。为什么长页要多？因为短页本来就是一页一块，四种切法切出来几乎一样，测不出差异；真正能暴露差异的是长页、表格页、公式页和一页讲多个主题的页。

类别上也做了覆盖：概念 21 道，机制 14 道，tutorial 13 道，assignment 11 道，表格 6 道。64 道题只有一个 gold page，q027 有两个，因为那个问题需要同时看代码页和解释页。gold page 的估算 token 中位数是 239.5，平均 255.7，p90 是 446，最大 713。这个分布说明题目确实偏向内容较多的页，而不是只考短小的定义。

题目用英文，因为语料是英文。英文问题可以直接拿去检索，不需要额外引入一层中文到英文的改写。生产环境里系统会先让 DeepSeek 改写查询，但这次实验把改写冻结成“直接用原问题”，这样每次检索的输入完全一样，切法才是唯一变量。

## 4. 对比指标及方法

主指标是页级 nDCG@5。做法是先把返回的块按排名展开成页：第一块覆盖第 27 页，就把第 27 页放第一；第二块覆盖第 29 页，第 29 页放第二；如果后面的块又覆盖第 27 页，就跳过，因为页已经出现过。然后取前五页，看正确答案页排在哪里。q058 的例子里，正确答案第 29 页排第二，nDCG 是 1 除以 log2(3)，约 0.63；排第一是 1.0，排第三是 0.5，排第五是 0.386。这个指标能区分“排第一”和“勉强进前五”，比单纯的命中率更细。

辅助指标有三个。`hit@3` 看前三页有没有命中，回答“用户翻三页能不能找到”。`hit@5` 看前五页。`context_tokens@5` 看为了拿到前五页一共塞了多少 token，回答“这个提升值不值”。还有一个诊断指标是真实 BGE token 超过 512 的比例，它不参与打分，但能解释为什么某些方案在长页上吃亏。

检索这边只变切法，其他全部锁死。同一个 BGE-M3，1024 维，CLS pooling，L2 归一化，CPU，`max_length=512`，batch 16。同一个 FTS5 的 `unicode61` 分词和 BM25。同一个 RRF，`k=60`，两路权重 1:1，每路取前 30 个候选。同一个 k 值，取 3、5、10。同一份查询文本。整个实验里唯一在动的就是“怎么切”。

统计上，同一道题上两个方案的结果是配对的。我们算每道题的差值，再用 bootstrap 按题重采样 2000 次，算 95% 的置信区间。如果区间跨零，就说明这个差异可能只是题目抽样带来的运气，不能说谁赢。命中率是 0 或 1，额外用 McNemar 检验。主比较只做一个：hybrid 检索下的页级 nDCG@5。其他比较，比如 lexical、dense、不同类别、不同页长，都是探索性的，用来解释现象，不用来下最终结论。

判定规则提前写死：主指标显著更好、前三页命中不退步、上下文成本不超过 baseline 的两倍，三条都满足才换。这样无论结果往哪边走，都有话说。如果结果是打平，那就保留现有方案，并把“打平”本身写进报告，这也是有效结论。

整套流程是：把 365 页分别按九种方式切块，把每块的 `embed_text` 送进本地 BGE-M3，把块、全文索引和向量写进九个独立的临时 SQLite，然后用同一批问题分别跑 hybrid、lexical、dense 三种检索，把返回的块展开成页，算指标，最后按题配对做统计。临时库放在 `data/index/`，向量缓存放在 `data/cache/`，汇总结果放在 `results/full-01/`。这些都在实验文件夹里，不碰生产代码。

## 5. 结果

先看最关心的 hybrid 检索。下表是 51 道 test 题上的页级 nDCG@5，括号里是 95% 置信区间。

| 组合 | nDCG@5 | 前五页 token | hit@3 |
|---|---:|---:|---:|
| `page_only` | 0.8512 [0.7562, 0.9330] | 1059 | 0.882 |
| `page_first_128` | 0.8405 [0.7563, 0.9160] | 586 | 0.882 |
| `page_first_256` | 0.8384 [0.7463, 0.9197] | 760 | 0.882 |
| `page_first_450` | 0.8487 [0.7532, 0.9314] | 937 | 0.882 |
| `recursive_128` | 0.8130 [0.7188, 0.8949] | 596 | 0.824 |
| `recursive_256` | 0.8488 [0.7580, 0.9272] | 811 | 0.882 |
| `recursive_450` | 0.8562 [0.7677, 0.9343] | 1008 | 0.882 |
| `semantic_450` | 0.8562 [0.7677, 0.9343] | 1008 | 0.882 |
| `cross_page_450` | 0.8368 [0.7463, 0.9143] | 944 | 0.902 |

从表面看，`recursive_450` 和 `semantic_450` 最高，0.8562，比 baseline 高 0.005。但这个差距在统计上站不住。51 道题里，1 道赢，49 道平，1 道输，McNemar p 值是 1.0，置信区间是 [-0.0077, 0.0228]，跨零。换句话说，这个提升可能只是题目抽样的运气。所有其他组合相对 baseline 的置信区间也都跨零，没有任何一个切法显著更好。

`page_first_450` 和 `page_only` 几乎一模一样。51 道题里 50 道排名相同，只有 q058 从第二名掉到第三名，所以平均分从 0.8512 变成 0.8487。但它省了 122 个 token，真实截断率从 12.33% 降到 10.99%。这就是保留它的理由：没有证据说它更好，但也没有证据说它更差，而它更便宜、截断更少。

如果上下文成本变成主要矛盾，`page_first_256` 是更合适的折中。它掉 0.013 nDCG，统计上不显著，token 从 1059 降到 760，省了 28%，截断率从 12.33% 降到 4.66%。`page_first_128` 更省，token 586，截断 1.57%，但产生 48 个超预算块，单题波动更大，有 3 胜 4 负。它适合“非常在意成本、能接受一点排名波动”的场景。

真正值得继续挖的是 dense 那一路。只用向量检索时，`page_first_128` 是 0.8941，`page_only` 是 0.8323，提升 0.0618，9 胜 3 负，token 少 454，但置信区间下限是 -0.0031，刚好碰到零。这个信号和截断率对得上：块越小，512 token 窗口里装下的原文越完整。hybrid 把这个收益冲掉了，因为词法臂更喜欢整页。所以下一步不是再试第五种切法，而是调 RRF 权重或者做 dense-first 路由，看看能不能把小块的 dense 收益带进 hybrid。

`cross_page` 不行。它只有 0.8368，截断率 16.26%，是九个组合里最差的。它把多页合并成一块，向量的主题被平均掉，页排名反而下降。这说明在这个语料上，页边界不是限制检索上限的东西。`semantic` 在 dev 选出的 0.25 阈值下几乎退化成页级切分，和 `recursive_450` 只差一个块，所以指标完全一样；0.30 阈值也一样是 0.8562，0.35 降到 0.8393。这条路线在这个语料上没有收益。

按类别和页长拆开看，结论更清楚。表格类所有方案都是 1.0，因为所有切法都不会把表格切开，这个语料测不出表格保留的差异。tutorial 是最难的类别，baseline 0.628，`cross_page` 0.686，`recursive_450` 0.652，小切法略有帮助。assignment 和 concept 基本在 0.86 到 0.93 之间，差异很小。按页长看，短页上 baseline 0.921，切小反而降到 0.902；长页上 baseline 0.824，`recursive_450` 0.844，`cross_page` 0.857，切小确实有帮助。也就是说，切块在长页上赚一点，在短页上亏一点，最后平均下来打平。

错误分析也支持这个判断。q011 和 q025 是公式页，OCR 文本噪声大，答案页在十个方案里都很难进前五；q042 是相邻两页都在讲课程政策，检索分不清；q054 和 q062 是概述页排在了细节页前面，问题措辞本身更像在问概述。这些失败不是换切法能解决的，真正的杠杆是查询改写、rerank、公式页 OCR，以及页内 span 级评估。

### 5.2 融合权重专项验证

切块打平以后，最便宜的下一个变量是 RRF 的两路权重。原来词法路和稠密路是 1:1，我们试了偏稠密的 2:1 和偏词法的 1:2，只挑目前 hybrid 表现最好的三个不同组合：`recursive_450`、`page_only`、`page_first_450`。`semantic_450` 没有选，因为它和 `recursive_450` 的块几乎一样，指标也完全一样，放进来只是重复。

| 组合 | 稠密:词法 | nDCG@5 | hit@3 | token@5 | 相对 1:1 的 ΔnDCG@5 | 胜/平/负 |
|---|---|---:|---:|---:|---:|---:|
| `recursive_450` | 1:1 | 0.8562 | 0.882 | 1008 | - | - |
| `recursive_450` | 2:1 | 0.8302 | 0.863 | 1018 | -0.0260 [-0.0603, 0.0005] | 2/45/4 |
| `recursive_450` | 1:2 | 0.8412 | 0.882 | 994 | -0.0150 [-0.0367, 0.0000] | 0/48/3 |
| `page_only` | 1:1 | 0.8512 | 0.882 | 1059 | - | - |
| `page_only` | 2:1 | 0.8302 | 0.863 | 1076 | -0.0210 [-0.0518, 0.0026] | 1/47/3 |
| `page_only` | 1:2 | 0.8218 | 0.882 | 1042 | -0.0295 [-0.0584, -0.0072] | 0/46/5 |
| `page_first_450` | 1:1 | 0.8487 | 0.882 | 937 | - | - |
| `page_first_450` | 2:1 | 0.8302 | 0.863 | 965 | -0.0184 [-0.0498, 0.0051] | 2/46/3 |
| `page_first_450` | 1:2 | 0.8337 | 0.882 | 923 | -0.0150 [-0.0367, 0.0000] | 0/48/3 |

所有调整都比 1:1 差。唯一置信区间不跨零的是 `page_only` 的 1:2，但它是 -0.0295，是退步，不是提升。其他区间虽然跨零，点估计也全是负的，胜平负里胜的题很少、平局很多。所以 1:1 仍然是这三个组合的最佳融合权重。

这里有一个重要的解释限制。三个组合都是页级的，dense-only 分数几乎一样（0.8323、0.8319、0.8323），所以当稠密权重加大到 2:1，融合结果就退化成同一个稠密排名，三行都是 0.8302。也就是说，这次扫描并没有真正检验“稠密偏重能不能放大 128 小块的收益”，因为选进来的三个组合都不是 128 小块。它排除的是“在现有最好的页级组合上，单靠调权重就能提升”这个便宜方案，不能排除“让 `page_first_128` 或双粒度索引配稠密权重会更好”这个更贵的方向。

### 5.3 双粒度索引最小验证

最后做一个最小双粒度实验：词法路用 `page_first_450` 的页级块，稠密路用 `page_first_128` 的 128 子块，两路先各自展开成页、去重，再在页级做 RRF，`k=60`。先跑 1:1，再跑稠密 2:1。模型拿到的是整页文本，所以成本按页算。

| 系统 | nDCG@5（95% CI） | hit@3 | hit@5 | 前五页 token |
|---|---:|---:|---:|---:|
| `page_first_450` hybrid | 0.8487 [0.7532, 0.9314] | 0.882 | 0.882 | 1147.9 |
| `page_first_128` dense only | 0.8941 [0.8280, 0.9525] | 0.941 | 0.980 | 1141.5 |
| 双粒度 1:1 | 0.8567 [0.7652, 0.9340] | 0.863 | 0.902 | 1144.8 |
| 双粒度稠密 2:1 | 0.8596 [0.7819, 0.9293] | 0.902 | 0.941 | 1136.5 |

双粒度 1:1 比 `page_first_450` 高 0.0081，置信区间 [-0.0059, 0.0305]，2 胜 48 平 1 负，不显著。把页级融合改成稠密 2:1 后，nDCG 变成 0.8596，比 baseline 高 0.0110，置信区间 [-0.0333, 0.0595]，5 胜 42 平 4 负；相对 1:1 只高 0.0029，区间 [-0.0374, 0.0447]，5 胜 43 平 3 负。两个区间都跨零。

更明显的变化在命中率。稠密 2:1 把 hit@3 从 0.863 拉到 0.902，hit@5 从 0.902 拉到 0.941，前五页 token 还略降到 1136.5。这是目前唯一一个把页排名往稠密方向拉、又没有明显退步的设置。但它仍然远低于 dense-only 的 0.8941，说明页级融合没有把稠密的全部收益带过来。这个结果值得再确认一次，但不能当成已经成立的提升。

整页 token 成本在四行里都在 1140 左右，因为模型仍然拿整页文本；双粒度多出来的成本是离线给 128 子块算向量，不是在线上下文。如果下一步改成只注入子块，成本会降，但上下文也会变得不完整。

所以最后的结论是：**保留 `page_first_450` 作为生产默认，融合权重保持 1:1。** 没有证据表明任何切法显著更好，它在统计上和 baseline 打平，但更便宜、截断更少。如果以后成本优先，选 `page_first_256`。不采纳 `cross_page`，不采纳当前配置下的 `semantic`，也不在现有页级组合上调 RRF 权重。双粒度稠密 2:1 是目前唯一值得再确认一次的设置：它把 hit@3 和 hit@5 拉高，nDCG 也略高于 baseline，但区间仍然跨零，还不能当成结论。下一步应该围绕这个设置再拿更多题确认，或者继续做多分辨率索引和 reranker，而不是回到单一切法上。

这个结论有边界。51 道题样本小，只能排除大效应，不能排除小效应；64 道题只有一个 gold page，页级指标对长块天然友好，所以我们同时报了 token 成本和截断率；页级指标看不到“页被召回了但答案在截断的尾部”这种情况，所以单独统计了超过 512 token 的比例；公式页的 OCR 噪声很大，q011 和 q025 的失败主要来自这里；语义阈值只在 14 道 dev 题上选，所以我们补了 0.25、0.30、0.35 的敏感性表。把这些说清楚，别人才知道这个结论的适用范围。
